# 通用 PRD 模板 v0.1：来源与取舍

## 1. 结论

一期通用模板位于 `PRD_TEMPLATE_v0.1.md`，模板 ID 为 `better-product-graph.prd.general`。它从 Better-Product-Plan 的 `references/product-prd-template.md` 派生，保留完整产品规格能力，删除特定公司、金融交易、投教和监管报备语境，适用于一般前后端结合的产品增量。

它是一份 **Draft 模板**，不是冻结发布版，也不是第二份 Product Spec。Better Product Graph 的 Agent 仍在同一次 `prd.generate` 过程中完成内容组织和模板表达；只有最终 PRD 是正式的人类交付合同。

## 2. 设计原则

1. **先让人理解，再补充检查细节**：正文先呈现目标、问题、范围、关键流程、规则和验收；版本、审计和条件检查保留，但不打断主叙事。
2. **完整规划不等于把所有事项塞进一份 PRD**：模板只描述已激活的 PRD Slice，并引用 Parent Product Plan、Product Decision 和 Roadmap，不重新做产品决策。
3. **不生成第二真源**：父 Plan、Slice、Decision、Knowledge、Review、Ready 和 Release 使用 exact refs；正文只给读者一个生命周期追溯入口，不复制内部状态账本。
4. **条件化而非强行填满**：多语言、无障碍、数据上报、BI、法律合规等不相关时允许简短 `不适用 + 理由`，不产生大片空表。
5. **不允许裸未决项**：未决信息必须同时记录确认人或有效来源，以及它对当前 PRD 的影响。
6. **不强制 MoSCoW**：改用“本期必须 / 可后置 / 明确不做”，避免模板反过来扩大已经确认的切片范围。
7. **保留通用交付能力**：兼容性、老用户影响、数据上报、多语言、灰度、降级、回滚和跨团队同步不能因去领域化而丢失。
8. **分开 Evals 判断与准备进度**：适用性只判断普通 AC 是否足够、Evals 是建议还是交付必需；生成、审查或缺输入属于独立 Fulfillment 状态，不能反向篡改适用性。
9. **为测试设计保留轻量接口**：PRD 可以引用或简述测试意图、场景、AC 映射、边界与回归建议，但正式测试用例、测试代码、runner、结果和 verdict 仍属于未来 Test Graph。

## 3. 原模板主要部分的 Disposition

| 原模板部分 | 处置 | 在通用模板中的位置 | 理由 |
|---|---|---|---|
| 变更日志 | 保留并增强 | 附录 C；摘要显示当前版本主要变化 | 保留版本轨迹，但不让历史表格阻断首次阅读；增加 supersedes 及 Review/Release 影响。 |
| 需求范围 / 适用端 | 保留并通用化 | 第 2 节 | 对任何产品需求都必要；扩展到客户端、服务端、API、版本、用户和地域边界。 |
| 产品三问 | 通用化 | 第 1 节 | 保留用户、问题、价值和时机判断，但改成目标、当前阻碍、证据和成功边界，避免口号化。 |
| 相关 OKR | 条件化 | 第 1.4、8.1 节 | 不强制每个项目都有正式 OKR；有则引用，没有则用产品目标与可观察指标，不能伪造 OKR。 |
| 常规 Checklist | 拆分并通用化 | 第 6—10 节及附录 D | 将真正通用的兼容、长文案、数据、SDK、跨团队影响分配到对应正文，避免一张巨表重复正文。 |
| 品牌 / 金融业务 / 投教专属检查 | 删除 | 不进入通用模板 | 属于项目 Profile 或领域模板，不应成为所有项目的默认负担。 |
| 项目专属 Checklist | 条件化 | 第 10、11 节；未来项目 Profile 扩展 | 保留扩展能力，但不要求通用模板自行猜测所有领域检查。 |
| 合规 Checklist | 通用化并条件化 | 第 6.3、10.1 节 | 保留数据、隐私、知识产权、合同和内容安全等通用边界；具体行业监管项交给领域 Profile 与专业 Owner。 |
| 功能说明 / 模块优先级 | 保留并改写 | 第 2.1、3.2 节 | 模块与范围仍必要；优先级改为“本期必须 / 可后置 / 明确不做”，服从上游 Slice。 |
| 依赖关系 | 保留并增强 | 第 2.4 节 | 增加跨 PRD 共享合同和 exact refs，帮助小 PRD 保持解耦而不丢失整体关系。 |
| 流程图 | 条件化 | 第 3.3 节 | 简单流程优先文字；只有关系复杂时才用图，避免为了模板画图。 |
| 模块详述 | 保留并增强 | 第 4 节 | 保留用户故事、触发、规则、分支、异常和 AC；增加状态、权限、退出条件和前后端行为边界。 |
| AI / 内容处理专属小节 | 通用化并条件化 | 第 5.2 节及模块内规则 | 不将 AI 特殊结构强加给所有需求；用三档适用性判断普通 AC 是否足够，并把 Evals 生成/审查/输入受阻放入独立准备状态。 |
| 测试设计参考 | 条件式新增轻量引用 | 第 5.3 节 | 为功能测试意图、场景、AC 映射、边界/异常和回归建议提供交接点，同时不越权生成未来 Test Graph 的正式测试资产或结论。 |
| 性能要求 | 保留并条件化 | 第 6.1 节 | 使用基线、目标、测量位置，避免无来源的统一时延阈值。 |
| 安全要求 | 保留并通用化 | 第 6.3 节 | 权限、敏感数据、滥用和第三方依赖是通用风险。 |
| 兼容性要求 | 保留并增强 | 第 7.1 节 | 明确新旧版本并存、老用户和历史数据、API/Schema 兼容及迁移。 |
| 无障碍访问 | 条件化保留 | 第 6.4 节 | 需要时是重要质量要求，不适用时只需说明理由。 |
| 降级 / 灰度 / 回滚 | 保留并增强 | 第 7 节 | 支撑小步实验、快速验证和安全回退，属于通用交付边界。 |
| 数据埋点 | 保留并通用化 | 第 8.2 节 | 事件表只在需要时出现；保留上报质量、数据最小化和未申请 ID 的责任边界。 |
| 数据分析思路 / BI | 保留并通用化 | 第 8.1、8.3 节 | 连接成功指标、分析问题和报表口径，不限定某一数据组织方式。 |
| 多语言文案 | 保留并增强 | 第 9 节 | 保留多语言、长文案、地区格式、审核和 Copy ID / 版本兼容。 |
| 支撑材料 | 保留 | 附录 A | 支持证据追溯；没有材料时必须说明影响和补充来源，不留空占位。 |
| 决策日志 | 改为引用 | 附录 B | PRD 不重新做 Product Decision；只引用既有决定并说明对本 PRD 的影响。 |
| 待确认事项 | 保留并强化 | 第 11.3 节 | 每项必须包含 Owner/source、影响和最晚确认点，禁止裸 `TBD`。 |

## 4. Better Product Graph 通用扩展

相比上游模板，本版本只加入 PRD 交付所需的最小通用扩展：

- Parent Product Plan、PRD Slice、Product Decision、Knowledge Snapshot 的 exact refs。
- 当前 PRD 增量对阶段结果的贡献。
- 已确认事实、假设、未知、待验证的边界。
- Shared Contract 与跨 PRD 依赖。
- Product Evals 三档适用性、独立 Fulfillment 状态与 Eval Pack ref。
- 条件式 Test Design Contract / 测试设计参考 ref。
- Template ID/version、PRD version/status，以及压缩为一个追溯入口的 Review/Ready/Release refs。

这些字段为人类理解和交付追踪服务，不包含内部全量 Audit Event、State Controller 计算字段或隐藏推理。

## 5. 未来模板扩展方式

一期只有 `general` 模板。未来模板采用简单的“基于 general 增加或覆盖条件章节”，不建立注册中心或新模板服务：

- `frontend` 可加强交互状态、响应式布局、视觉反馈、无障碍、文案和端版本兼容。
- `backend-service` 可加强 API 合同、数据模型、幂等、一致性、容量、迁移、可观测性和降级。

专用模板不得删除 general 的目标、范围、关键规则、验收、证据/未知边界、版本与来源引用；重复内容优先覆盖而不是复制两份。是否需要正式继承语法、模板选择器和兼容 Validator，留待真实模板替换原型后决定。

## 6. 本轮仍需 Review

1. `general` 的正文长度是否适合首批真实 PRD；轻量 PRD 是否需要由 Renderer 自动折叠更多条件章节。
2. Evals 两维字段是否能防止“输入缺失”被误判为“不需要 Evals”，并在真实 PRD 中保持直白。
3. 轻量 Test Design Contract ref 是否足以支撑未来 TDD-ready 交接，又不会被误读成已经完成正式测试设计或执行。
4. 第一批前端、服务端真实样本是否证明需要专用模板，还是项目 Profile 已足够。
5. 当前 Draft 通过真实 PRD 试跑和可读性审查后，再决定是否升级为冻结的 v1.0 默认模板。
