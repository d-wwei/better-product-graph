# 库存预占结果回调

## 现状

库存服务已经支持预占结果回调。订单提交预占后，库存服务会在三秒内调用订单回调接口；回调失败会自动重试三次，订单服务能够按 `reservation_id` 幂等处理。

当前回调合同如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `reservation_id` | string | 预占记录 ID |
| `order_id` | string | 订单 ID |
| `result` | enum | `SUCCESS` 或 `FAILED` |
| `reason` | string | 失败原因 |

订单服务收到 `SUCCESS` 后进入支付流程，收到 `FAILED` 后释放订单。三次回调失败后，库存服务把任务放入人工处理队列。这个机制已经可以供移动端新结算流程使用。

## 验收

- 回调在三秒内到达。
- 重复回调不会重复推进订单。
- 三次失败后任务进入人工处理队列。

## 备注

以上内容来自本轮产品讨论，研发实现、联调和线上验证尚未开始。
