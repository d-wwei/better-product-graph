# 售后退款状态展示

## 一句话说明

售后退款会经过平台、商家、物流和支付渠道。页面必须用一个状态说明当前由谁处理、用户能做什么，以及什么情况会进入下一步。

## 状态表

| 状态 | 用户看到什么 | 当前责任方 | 用户可执行动作 | 离开条件 |
|---|---|---|---|---|
| 草稿 | “申请尚未提交” | 用户 | 编辑、提交、删除 | 用户提交申请 |
| 已提交 | “等待平台检查” | 平台 | 撤回 | 平台完成基础检查 |
| 待补充材料 | “请补充材料” | 用户 | 补充、撤回 | 用户重新提交材料 |
| 商家处理中 | “等待商家处理” | 商家 | 查看进度 | 商家同意、拒绝或超时 |
| 商家未同意 | “商家未同意退款” | 用户 | 申诉、关闭申请 | 用户申诉或关闭 |
| 待寄回 | “请寄回商品” | 用户 | 填写物流、撤回 | 用户提交有效物流单号 |
| 寄回途中 | “商品寄回中” | 物流 | 查看物流 | 商家签收或物流异常 |
| 物流异常 | “物流异常，请处理” | 用户与物流 | 更新物流、联系客服 | 异常解除或平台介入 |
| 平台仲裁中 | “平台处理中” | 平台 | 补充证据 | 平台给出结论 |
| 退款已批准 | “退款已批准” | 支付渠道 | 查看金额 | 支付渠道受理 |
| 退款处理中 | “退款处理中” | 支付渠道 | 查看预计时间 | 退款成功或失败 |
| 退款失败 | “退款失败，正在处理” | 平台 | 联系客服 | 重试成功或人工完成 |
| 退款成功 | “退款已到账” | 无 | 查看凭证 | 最终状态 |
| 已关闭 | “申请已关闭” | 无 | 查看原因 | 最终状态 |

## 共通规则

- 页面只能显示后端已经确认的状态，不能因为用户点击按钮就提前显示下一状态。
- 状态变化必须保留时间、责任方和原因。
- 最终状态仍可查看完整处理记录。

## 验收

- 每个状态都能找到当前责任方、用户动作和离开条件。
- 支付渠道尚未确认成功时不能显示“退款已到账”。
- 物流异常和退款失败都有明确恢复入口。
