# PRD 内审与交付

## 一页摘要

产品经理提交 PRD Candidate 后，独立 Reviewer 给出建议；主 Agent 处置建议并形成可追溯结果。只有当前 Candidate、Review 和处置记录精确一致，系统才把 PRD 标记为可交付。内审完成不等于外部团队已经批准。

## 读图先理解全局

![PRD 内审与交付流程](./assets/visual-002.svg)

文字摘要：Candidate 先经过独立内审；有采纳的修改时返回作者形成新 Candidate 并重新审查，所有建议有处置后再做一致性检查，通过后生成本地交付物。外部审批不在这条流程内。

## 三个角色

- 作者：生成和修订 PRD Candidate，不能替 Reviewer 给自己出具独立意见。
- Writing Reviewer：复述文档、指出理解断点并给出建议，不修改 Candidate，也不拥有批准权。
- Controller：只检查版本、引用和处置是否一致，不判断文章或图是否真正清楚。

## 正式产品合同

| 当前情况 | 下一步 | 对用户显示 |
|---|---|---|
| Candidate 尚未完成独立审查 | 等待 Review | “内审中” |
| Review 有建议且主 Agent 决定采纳 | 修订并重新审查新 Candidate | “修订中” |
| Review 建议均有采纳或不采纳理由 | 进入一致性检查 | “内审已完成” |
| 引用、版本或处置不一致 | 返回对应环节修复 | “交付准备未完成” |
| 一致性检查通过 | 生成本地交付物 | “可提交外部审核” |

“可提交外部审核”只表示本地 PRD 及其证据已经整理完成，不表示研发、测试、合规或管理者已经批准。

## 失败与恢复

- Candidate 内容变化后，旧 Review 自动失效，必须审查新版本。
- Reviewer 与作者是同一个执行实例时，独立性检查失败，重新派发 Reviewer；不能沿用这次意见。
- 某条建议没有处置时，返回 Review 汇总补齐记录；关注等级本身不阻塞交付。

## 验收

- 新 Candidate 不能复用旧 Candidate 的 Review。
- 每条建议都有采纳、暂不采纳或转上游处理的记录与理由。
- Controller 只依据 exact refs 和状态执行一致性检查。
- 最终文案不会把本地交付写成外部已经发送、接收或批准。

## 未知与下一步

真人是否能更快理解 PRD 仍需要单独观察式测试。本合同只规定 Reviewer 和确定性校验的职责边界。
