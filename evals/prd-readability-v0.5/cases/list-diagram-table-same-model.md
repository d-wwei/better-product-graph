# 订阅取消与权益到期

## 目标

让用户清楚订阅取消何时生效：支付渠道确认取消时立即停止下个周期续费，但已支付周期不会提前结束，用户在 `paid_until` 之前仍可继续使用已购权益。

## 状态列表

- `ACTIVE`：订阅有效，用户可以发起取消。
- `CANCEL_PENDING`：已受理请求，等待支付渠道确认；当前已支付权益继续有效。
- `CANCELLED`：支付渠道确认取消，不再续费；权益持续到已支付周期结束。
- `CANCEL_FAILED`：渠道拒绝或超时，订阅仍保持有效，用户可以重试。

## 状态图

```text
ACTIVE
  └─ 用户提交取消 → CANCEL_PENDING
                         ├─ 渠道确认 → CANCELLED
                         └─ 渠道拒绝或超时 → CANCEL_FAILED
```

## 状态表

| 状态 | 用户看到的含义 | 权益 | 下一步 |
|---|---|---|---|
| `ACTIVE` | 订阅使用中 | 当前周期有效 | 可以发起取消 |
| `CANCEL_PENDING` | 取消处理中 | 已支付周期仍可使用 | 等待渠道结果 |
| `CANCELLED` | 已取消续费 | 使用至 `paid_until` | 到期后停止权益 |
| `CANCEL_FAILED` | 取消失败 | 订阅仍保持有效 | 查看原因并重试 |

## 失败与验收

取消失败时，页面必须说明订阅仍有效且不会虚报“已取消”。渠道晚到的成功结果应把原请求更新为已取消；重复结果不能重复改变权益。用户在任何状态都能看到取消结果和已支付周期结束时间。

## 风险与未知

主要风险是渠道超时后又返回成功，导致页面短时显示旧状态。当前未知是不同渠道最晚回传时间；它只影响提示与重试时机，不改变权益边界。

## 下一步

支付负责人确认各渠道超时窗口后，用成功、拒绝、超时后成功三组样本核对页面状态与 `paid_until`。本需求不改变退款规则。
