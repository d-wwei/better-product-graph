# 自提柜取件与超时恢复

## 一句话结论

包裹入柜后，用户凭一次性取件码开柜；服务端确认柜门已经打开后才显示取件成功。取件码过期、柜机离线或柜门未开时，包裹不能被虚报为已取走。

## 主路径

1. 配送员完成入柜，用户收到取件码和柜机位置。
2. 用户在目标柜机输入取件码，系统核对包裹、柜机和码状态。
3. 柜门实际打开并由服务端确认后，订单变为“已取件”，原码失效。

核心状态与用户动作见[附录 A](#附录-a状态与提示文案)，事件追踪字段见[附录 B](#附录-b事件字段)，多语言含义见[附录 C](#附录-c多语言关键词)。附录补充定位，不重新定义上述成功边界。

## 关键失败与恢复

- 取件码过期：订单页刷新出新码，旧码立即失效。
- 柜机离线：不显示成功，网络恢复后用户可重试。
- 柜门未开：保留包裹“待取件”，并给出换柜或客服入口。
- 包裹已经取走：重复请求保持幂等，展示首次成功时间。

## 风险与未知

主要风险是柜门传感器晚报导致用户实际开柜但页面仍等待。当前未知是各柜机厂商最晚回传时间；在确认前系统不提前显示成功，并保留人工核查入口。

## 下一步

先用正常开柜、离线恢复和传感器晚报三类样本核对服务端状态，再由履约负责人确认人工核查时限。

## 核心验收

- 一个取件码只能成功使用一次。
- 非目标柜机不能打开柜门。
- 没有服务端开柜确认时不能显示“已取件”。
- 失败恢复不会消费仍有效的取件码。

## 附录 A：状态与提示文案

| 场景 | 用户看到什么 | 可以做什么 |
|---|---|---|
| 尚未入柜 | 包裹正在送往自提柜 | 等待通知 |
| 可以取件 | 请在目标柜机输入取件码 | 导航、取件 |
| 码已过期 | 已生成新取件码 | 使用新码 |
| 柜机离线 | 暂时无法确认，请稍后重试 | 重试、联系客服 |
| 柜门未开 | 未完成取件 | 换柜、联系客服 |
| 已经取件 | 显示首次成功时间 | 查看记录 |

## 附录 B：事件字段

| 事件 | 必要信息 | 产品用途 |
|---|---|---|
| 包裹入柜 | 订单、柜机、格口、时间 | 向用户开放取件 |
| 取件核对 | 订单、码版本、柜机 | 判断请求是否有效 |
| 柜门打开 | 订单、柜机确认、时间 | 形成成功证据 |
| 开柜失败 | 订单、失败类型、柜机 | 选择恢复入口 |
| 新码生成 | 订单、新旧码版本 | 保证旧码失效 |
| 人工核查 | 订单、原因、责任人 | 处理晚报与设备异常 |

## 附录 C：多语言关键词

“待取件”“取件码过期”“柜机离线”“柜门未开”“已取件”在所有语言中必须保持相同状态含义。具体翻译由本地化流程维护。

## 不在范围

本需求不改变配送入柜规则、超时收费、退款或柜机供应商结算。
