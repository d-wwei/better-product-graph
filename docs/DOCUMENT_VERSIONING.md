# 文档版本管理规则

生效日期：2026-08-18

## 核心规则

1. 任何已经向用户交付、引用或确认过的正式文档，交付后立即冻结。
2. 后续修改不得直接覆盖原文件，必须创建一个新版本文件。
3. 新版本必须在对应目录的 `CHANGELOG.md` 中记录版本号、日期、变更内容、状态和上一版本路径。
4. 旧版本永久保留，不因新版本发布而删除或改写。
5. 只有专门设计为可变入口的索引文件和 `CHANGELOG.md` 可以增量更新；正文版本文件不可变。

## 版本号

- Patch：措辞、排版或小范围澄清，不改变核心结构，例如 `v0.1 -> v0.1.1`。
- Minor：增加章节、调整流程或改变部分设计，例如 `v0.1 -> v0.2`。
- Major：改变系统边界、核心模型或不兼容的架构决策，例如 `v0.9 -> v1.0`。

## 文件命名

```text
<DOCUMENT_NAME>_v<major>.<minor>[.<patch>].md
```

例如：

```text
PRD_GRAPH_v0.2.md
PRD_GRAPH_v0.2.1.md
PRD_GRAPH_v1.0.md
```

## 修改流程

1. 确认当前最新版本。
2. 根据修改性质确定新版本号。
3. 复制当前版本内容到新版本文件。
4. 只修改新版本文件。
5. 在 `CHANGELOG.md` 记录变更和 supersedes 关系。
6. 验证旧版本内容和 hash 未发生变化。
7. 将新版本交付用户确认；未确认前标记为 `draft`。

## 禁止行为

- 不得使用覆盖写修改已交付正文。
- 不得把旧版本重命名后假装它从未存在。
- 不得只保留“最新版”而删除历史版本。
- 不得在没有 Changelog 的情况下发布新版本。
- 不得把 draft 默认为 approved/current。
