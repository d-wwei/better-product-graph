# ADR-007：研发仓库与正式发布仓库分离 v0.1

- 状态：Accepted
- 日期：2026-08-21
- 范围：Better Product Graph 的 GitHub 同步与正式发布
- 取代：无

## 决定

Better Product Graph 使用两个职责不同的 GitHub 仓库：

1. 私有研发仓库 `better-product-graph-dev` 是唯一研发真源，保存源码、测试、完整 Git 历史、研发分支、审计材料、施工文档、实验 Adapter 和尚未发布的候选内容。
2. 正式发布仓库 `better-product-graph` 只接受从研发仓库生成的发布快照，保存可安装产品、必要测试、正式文档、当前 Roadmap、已采纳核心决策和发布追溯信息。

发布方向严格单向：

```text
better-product-graph-dev
        │
        │ 测试、审计、选择、生成发布快照
        ▼
better-product-graph
```

正式仓库不作为独立研发地点，也不把修改反向合并到研发仓库。任何正式版本必须记录来源研发 commit、产品版本、生成日期和发布文件清单。

## 本地内容边界

即使研发仓库是私有仓库，也不提交凭证、`.env`、Host 缓存、临时 Worktree、锁文件、可重复生成的构建目录或新的 Graph 运行状态。需要长期保存的产品文档、审计结论和研发证据应进入具名、可审计的正式目录，而不是依赖本地运行缓存。

## 正式仓库边界

正式仓库不继承研发仓库 Git 历史，以避免已删除的过程稿、运行记录、机器路径或实验内容仍可通过历史访问。正式仓库只包含当前发布所需内容；历史正式版本由正式仓库自己的 Release、Tag 和 Changelog 管理。

## 没有采用的方案

- 单仓库加公开分支：分支不是安全或历史隔离边界，容易让过程文件通过历史、Tag 或错误合并进入公开范围。
- 两个仓库双向开发：会形成两个真源，造成版本、修复和文档漂移。
- 手工复制而不记录来源：无法证明发布内容来自哪个研发版本，也难以可靠复现。
